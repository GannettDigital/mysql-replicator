## Current prototype grammar — engine policy superseded

| Operation | Accepted shape |
| --- | --- |
| CREATE | One table, explicit `ENGINE=InnoDB`, supported columns and one integer primary key |
| ALTER ADD | One nullable non-key column, appended or positioned FIRST/AFTER |
| ALTER DROP | One existing non-key column |
| RENAME TABLE | One pair of distinct names in the same database |
| DROP TABLE | One existing table |

Column types remain signed/unsigned INT/INTEGER and BIGINT, VARCHAR(n) and
VARBINARY(n). VARCHAR requires explicit `CHARACTER SET utf8mb4 COLLATE ...` on the
column; it never guesses a source database's inherited encoding. Accepted
collations are utf8mb4_bin, utf8mb4_general_ci, utf8mb4_unicode_ci and source
utf8mb4_0900_ai_ci. The last maps explicitly to utf8mb4_unicode_ci on 5.7.
Only a NULL default is accepted. CREATE permits inline or table-level primary
keys, and makes the key nonnullable. Identifiers remain ASCII and at most 64 bytes;
backtick quoting and doubled backticks are supported.

For example:

```sql
CREATE TABLE poc.orders(payload VARBINARY(100) NULL, id INT PRIMARY KEY) ENGINE=InnoDB;
ALTER TABLE poc.orders ADD note VARCHAR(100) CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci NULL FIRST;
ALTER TABLE poc.orders DROP COLUMN payload;
RENAME TABLE poc.orders TO poc.orders_v2;
DROP TABLE poc.orders_v2;
```

The parser consumes the entire statement and generates fresh quoted target SQL.
It does not forward raw source SQL. CREATE maps InnoDB to MyISAM. A default database
in the query event resolves unqualified names; otherwise names must be qualified.
The exact trailing `/* generated by server */` suffix emitted for DROP by MySQL
8.4 is accepted (local pinned source: `sql/sql_table.cc`, Drop_tables_query_builder).
Other comments, string literals, expressions and additional statements fail closed.

Unsupported examples include IF EXISTS/IF NOT EXISTS, temporary tables, multi-table
rename/drop, multi-clause ALTER, MODIFY/CHANGE, TRUNCATE, indexes/key changes, generated
columns, AUTO_INCREMENT, foreign keys, partitioning, CREATE ... SELECT, database DDL,
non-NULL defaults and unsupported types. They stop capture/application with a retained
pending group and raw relay evidence, without executing target SQL.

Query-event status bytes remain preserved in the relay/decoder output. This grammar
avoids session-dependent expressions and literals, uses explicit types/encoding, and
executes generated SQL under the fixed target session settings. It does not replay
arbitrary source SQL modes or claim general statement-replication compatibility.
The source-only live inspection command retains its conservative DDL rejection;
offline inspection can expose opaque statement groups for debugging.

## Application and state ordering

Only a standalone named-GTID query group qualifies. Ordinary DML retains its existing
single-statement/single-table checks. Before DDL, verify writer ownership and native
replication exclusion. Inspect the target's complete supported schema and compare
any cached version; CREATE/rename destinations must be absent. Validate the predicted
after-schema before execution. The source's current information_schema is never used
to interpret an older binlog event.

Sync the relay, persist the PENDING group and DDL intent (including target SQL and
before-schema reference), then execute once. Read back and verify the after-schema
or absence. In one SQLite transaction, retire the old schema version, insert the
new version if any, mark the DDL intent DONE, complete the source group, and advance
GTID/position/counters. Later table maps validate against the new schema, including
changed column order. Rename and drop invalidate old names; drop/recreate gets a
new version. Decoder query boundaries also clear cached table maps.

The target writer advisory lock remains held for the whole run. DDL has implicit
commits and does not use the DML table WRITE lock. Other administrative writers must
remain excluded operationally; the advisory lock does not fence outside clients.
The current target query timeout is 10 seconds, including DDL; this is a bounded
POC setting, not qualification for long-running production ALTER operations.
A timeout, lost response or failed after-check leaves the DDL intent pending and stops, even
if MySQL already changed the schema. There is no automatic repair/rollback/retry.

SQLite schema version is now 3. `schemas.current` distinguishes active descriptions;
`retired_at`, discovery time, source coordinate and `event_hash` identify versions.
A DDL-created description has no wire columns until observed in raw table-map events;
its fingerprint identifies the DDL event. `ddl_intents` records before/after schema
IDs, target SQL, status and timestamps. `state.ddl_applied` and progress `ddlApplied`
count DDL groups; `transactionsApplied` counts all completed source groups, while
`rowsApplied` counts DML rows only.

Existing age-gated, pressure-triggered cleanup also deletes eligible completed DDL
intents and retired schema versions only after all retained row/DDL references are
gone. Pending work and current schemas stay pinned. GTID coverage is never expired.
Current schemas remain capped at 64; old versions share the hard SQLite budget.
Raw relay rotation and crash/reconnect recovery remain unimplemented.

## Existing prototype harness and review

Run `make test`, `make test-asan`, and `make ddl-suite`. The latter builds the cached
static Ubuntu runtime; `make ddl-suite ARGS=--skip-build` reuses that exact image.
Automation remains SwiftPM plus Make. DDL fixtures grant CREATE, ALTER and DROP in
addition to the existing DML, locking, visibility and session privileges.

The three-server suite runs file/position with MINIMAL metadata and GTID with FULL
metadata. Each mode applies 14 interleaved DDL/DML groups, checks column order/types/
nullability and rows after every step, checks engine/collation transformations,
renames, and drops/recreates the same name with a different schema. It compares
ordered DDL/DML operation kinds against independently decoded source/native/Swift
binlogs and retains the full traces. This does not assert byte-identical binlogs.

The existing fixture demonstrates that explicit InnoDB CREATE remains InnoDB on
the native 8.4 reference; the prototype maps it to
MyISAM. Native and Swift engines are asserted separately. Row expectations and the
mapped schema are independent fixture oracles. Negative cases include an unsupported
DECIMAL ALTER and denied target CREATE, asserting stopped progress, no target change
for unsupported SQL and a pending intent for target SQL failure. The ordinary
`make dml-suite` remains the all-MyISAM reference for previously prepared tables.

Review parser rejection boundaries, generated SQL/engine policy, before/after schema
verification, durable intent ordering, and compaction references. This is a first DDL
subset, not full fleet schema compatibility or crash/reconnect qualification.
