# Second beta — 0.1.0-beta.2

Cross-version MySQL replication with live capture, offline replay and explicit
operator controls. This release includes all changes since the beta.1 development
baseline. It remains a prerelease for evaluation, without a stable 0.x state or
configuration compatibility promise.

## Replication and operations

- Adds the experimental **MySQL 5.7 → 8.4 InnoDB** profile alongside the existing
  **8.4 InnoDB → 5.7 MyISAM** profile. Shared DML, DDL and reconnect tests compare
  each topology with its same-version native reference. This is not Cloud SQL
  qualification; initial copying and server upgrades remain external.
- Records InnoDB recovery evidence, with explicit audited operator resolution.
  SQLite remains the source GTID checkpoint. Target commits and SQLite commits
  are separate: uncertain writes still require investigation, not automatic replay.
- Supports named PRIMARY/UNIQUE constraints such as
  `ALTER TABLE aux ADD CONSTRAINT val_uni UNIQUE(val)`.
- Adds bounded binlog `fetch`, local `replay` (including external mysqlbinlog
  archives) and stopped-state `support-bundle` collection. Bundles can contain
  sensitive SQL, rows and configuration; they are not uploaded automatically.
- Adds inclusive `source.stopAfterGTIDs` alongside transaction limits, and local
  `ctl status`, `ctl stop` and `ctl reload` for live and offline appliers. Reload
  changes only stop limits; it does not reseed state or replace connections.
  SIGTERM requests a graceful drain.

## Distribution and testing

- Linux **x86_64 only**: static `.tar.gz`, `.deb`, checksummed standalone installer
  and saved container image. No separate Swift, Rust or SQLite runtime is required.
  The installer defaults to the newest published release, including betas (`jq`
  required for discovery); `--version` retains explicit version selection.
- A non-root production image, promoted from tested CI bytes to
  `ghcr.io/gannettdigital/mysql-replicator:0.1.0-beta.2` after release publication.
  The saved image asset can also be loaded directly with `docker load`.
- Shared profile/options interfaces for tests, demos and benchmarks; measured
  migration of legacy coverage into shared scenarios. Runtime and harness
  coverage are reported separately, with downloadable reports and PR summaries.
  GitHub Pages is not required.

## Upgrade and limits

Cleanly stop the old process and back up configuration and the entire state
directory before upgrading. Resume existing state **without** `--initialize`.
SQLite schema version 9 pins the replication profile; supported older forward
state migrates on resume. Older binaries cannot reopen upgraded state. Do not
roll back the checkpoint independently of target writes. Switching profiles needs
a new externally prepared baseline and state directory.

Configuration and supported-schema restrictions still apply. Target triggers and
InnoDB foreign keys are rejected; supported source trigger definitions follow the
configured skip/reject policy. MyISAM is nontransactional. Compatibility collation
mappings are opt-in and can change equality, ordering and uniqueness. There is no
automatic repair of uncertain writes. Native macOS and Linux ARM64 binaries are
not included. Backups, cloning, Cloud SQL provisioning and MySQL upgrades are
outside this application.
