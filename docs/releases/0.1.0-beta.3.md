# Third beta — 0.1.0-beta.3

This prerelease adds target TLS options, simpler configuration examples and
controlled error skipping for offline replay. It includes the CI and qualification
fixes developed since the beta.2 development baseline.

The tested profiles remain **MySQL 8.4 InnoDB → 5.7 MyISAM** and the experimental
**MySQL 5.7 → 8.4 InnoDB** flow. Initial copying and database upgrades remain
external. Deployment in Cloud SQL still needs environment-specific testing.

## TLS and configuration

- Adds `target.tlsVerification: verify-ca` for targets with a trusted CA but no
  usable certificate hostname. An explicit `caFile` is required. Certificate
  chain and validity checks remain enabled; hostname matching is disabled.
  Default `verify-identity` behavior is unchanged, and source TLS is unchanged.
- Adds short `run.minimal.yaml` and `replay.minimal.yaml` templates alongside the
  complete commented example. Documents archive/support-bundle options, defaults,
  table filter lists, replay-only fields and TLS modes. Replay does not connect
  to the source or require source credentials.
- Includes all three YAML templates in the release downloads and standalone
  archive. Debian installs the minimal templates under
  `/usr/share/doc/mysql-replicator/examples/`.

## Live and offline error policy

- Adds stable error codes and an explicit `skipErrors.codes` allowlist for
  selected compatibility failures before target writes in both `run` and `replay`.
  Skips cover whole GTID groups; both modes still stop on errors by default.
- Allows `mysql.1062` duplicate-key skipping for InnoDB only after confirmed
  rollback of the whole source transaction. MyISAM SQL errors, issued DDL,
  uncertain commits and unconfirmed rollback still block.
- Makes per-GTID auditing optional through `recordSkippedTransactions` (default
  `true`). With `false`, skipped group/intent rows are removed and a covering
  checkpoint plus aggregate counts are retained atomically, without one snapshot
  per skip. Plan consistency checks and recovery using evidence maintained
  elsewhere when individual audit records are disabled.
- Reports persistent `skippedTransactionsByCode` counters. Existing storage limits
  still apply. Decoder/discovery continuation and blanket SQL-error skipping are
  not implemented; successful progress with skips does not prove data consistency.

## Testing and release process

- Consolidates full correctness, reconnect, recovery, offline, native-reference
  and demo checks into parallel PR/main CI matrices. The separate qualification
  workflow is retired. Jobs identify their topology and tested area.
- Fixes cleanup of the disposable native reference after expected failures,
  retaining failure evidence before later scenarios establish fresh baselines.
- Preserves shared build/cache reuse and promotes the exact Linux packages tested
  by successful main CI. Publishing the draft promotes the saved production
  image to GHCR; it does not rebuild the binary.
- Adds shared `offline-skip-errors` and `live-skip-errors` scenarios for both
  profiles, including
  optional audit, transaction rollback, stop/resume and MyISAM refusal. Unit
  checks cover checkpoint failure and bounded unaudited history.

## Install and upgrade

Linux **x86_64 only**: static `.tar.gz`, Debian `amd64` `.deb`, saved production
image and checksummed installer. No separate Swift, Rust or SQLite runtime is
required. Native macOS and Linux ARM64 binaries remain out of scope. The installer
selects the newest published release, including prereleases, or accepts
`--version 0.1.0-beta.3`.

Cleanly stop the old process, back up configuration and the entire state directory,
and resume without `--initialize`. Configuration version 2, SQLite schema version
9 and the codec ABI are unchanged by the application version bump. Error-skip
tables are created lazily when needed; existing skip counters survive restart.
Older binaries do not implement the new TLS/skip policies, so do not reuse those
settings with an older binary. Target and SQLite commits remain separate;
uncertain writes require operator investigation.
