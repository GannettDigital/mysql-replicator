# Fourth beta — 0.1.0-beta.4

This release adds two MySQL 5.7 target profiles. It improves preparation and
application of transactions. It also adds InnoDB foreign key support, connection
options, automatic support bundles, and CI measurements.

## Replication profiles

The shared test suite checks these profiles with MySQL 5.7.42 and 8.4.8:

| Source | Target | Configuration profile |
| --- | --- | --- |
| MySQL 8.4 InnoDB | MySQL 5.7 MyISAM | `mysql84-to-mysql57-myisam` |
| MySQL 5.7 InnoDB | MySQL 8.4 InnoDB | `mysql57-to-mysql84-innodb` |
| MySQL 5.7 InnoDB | MySQL 5.7 MyISAM | `mysql57-to-mysql57-myisam` |
| MySQL 5.7 InnoDB | MySQL 5.7 InnoDB | `mysql57-to-mysql57-innodb` |

The two 5.7-to-5.7 profiles are new in this release. Each profile uses shared
correctness, lifecycle and demo tests. Initial data copies and database upgrades
remain external operations. Deployment in Cloud SQL needs separate checks.

## Application and diagnostics

- Eligible InnoDB transactions use autocommit. Transactions that need several
  statements retain explicit transaction boundaries.
- A bounded queue prepares durable batches before target execution. Defaults
  allow eight source transactions per batch and eight prepared batches.
  A batch does not combine separate source transactions into one target transaction.
- Schema caches and fewer decoder probes reduce repeated work. Timing counters
  and target server counters help locate remaining costs.
- InnoDB targets support the qualified foreign key cases, including supported
  cascades. Validation rejects unsupported definitions and unsafe filter layouts.
  MyISAM targets still reject foreign keys. See the foreign key limits below.
- Sources and targets can explicitly disable TLS. This permits connections to
  servers without TLS and local targets. TCP connections in this mode have no
  transport encryption. TLS remains the default.
- An optional policy creates a support bundle when replication enters `BLOCKED`.
  Bundles can be directories or compressed archives. The test fixtures enable
  this policy. Bundles can contain sensitive data.

## Test measurements

Normal CI reports job, step, shard and case times. It reports catalog results and
Swift line coverage for each profile. Expanded coverage is optional. It adds
instrumented shared correctness and lifecycle runs without removing release tests.

A separate study compares cold and warm builds of the same commit. It uses
isolated caches and fresh runners. The study reports invalid comparisons if
cache restoration fails or the runner image differs. These reports guide later
CI changes. They do not establish a new CI time guarantee.

## Install and upgrade

Downloads include a static Linux x86_64 archive, a Debian amd64 package, and a
saved container image. Swift, Rust and SQLite runtimes are not required.
The installer selects the newest published release, including beta releases.
Use `--version 0.1.0-beta.4` to select this release.

Stop the old process cleanly. Back up the configuration and the full state
directory. Read the current configuration example before enabling new options.
Resume without `--initialize`. Do not apply new configuration options to an
older binary. Target commits and SQLite checkpoints remain separate. Uncertain
writes still need operator investigation.
