# Fifth beta — 0.1.0-beta.5

Release candidate. Integration qualification is pending. Review these notes after
the full PR checks pass and before publication.

This release improves offline replay diagnostics and command help. It adds
configurable large-event limits, large SQL packet handling, BIT, FLOAT/DOUBLE,
JSON, and spatial application paths. The four replication profiles are unchanged.

## Replay and command controls

- Replay checks the archive's initial GTID history against the saved checkpoint
  before a full scan. Errors identify the file and the missing history.
- Archive validation checks event CRCs, file continuity and transaction boundaries.
  It no longer calculates a hash for every complete binlog file. Successful
  validation can be reused within one replay session if the files are unchanged.
- Support bundles include archive inventory and startup diagnostics. Missing
  bundle output directories are created. Bundles can contain sensitive data.
- Each command has its own help. Run `mysql-replicator replay --help` for an
  example. Connection and replication settings remain in YAML.
- `replicator-lab` also has command-specific help for tests, demos, benchmarks,
  packaging, and catalog checks. Existing command names remain available.

## Values and limits

- Configurable limits replace the former 1 MiB value limit. Defaults allow 64 MiB
  per event and 256 MiB per source transaction. The maximum setting is 1 GiB.
  Target requests must also fit the target's `max_allowed_packet` setting.
- The SQL client splits and assembles large protocol packets. The new shared case
  checks large TEXT/BLOB writes, restart, replay and pending-row inspection.
- BIT supports widths through 64 bits, including primary keys and recovery output.
- FLOAT/DOUBLE retain their IEEE bits in decoding, SQL parameters and recovery.
  Fixed-scale forms, NaN and infinity remain unsupported.
- JSON supports complete documents, typed numeric and temporal values, and
  reconstruction of partial updates from FULL before images. Comparisons check
  JSON types as well as displayed values. Some legacy opaque types still lack an
  exact SQL constructor. They stop application instead of changing the type.
  Some typed JSON values require `CREATE TEMPORARY TABLES` permission on the target.

- Spatial columns retain their SRID and WKB bytes. All eight spatial types and
  SPATIAL index creation and removal are supported. MySQL 8.4 column SRID
  attributes remain outside the cross-version DDL syntax.

These additions have unit tests. The shared integration cases must pass before
release qualification is complete. Existing
profile, schema, transaction and recovery limits still apply.

## Development and tests

Changed-file selection uses the same rules for local checks and PR checks.
Run `make test-selection ARGS="--base origin/main"` to inspect the selection.
The final release PR uses `ci-full`. The final main commit runs the same full
suite. Release downloads use the packages tested by that successful main run.

## Install and upgrade

Downloads include a static Linux x86_64 archive, a Debian amd64 package and a
saved container image. The installer selects the newest published release,
including beta releases. Use `--version 0.1.0-beta.5` to select this version.
macOS and Linux ARM64 downloads are not provided.

Stop the old process cleanly. Back up the configuration and full state directory.
Read the configuration example before enabling new limits or column types.
Resume without `--initialize`. Archive manifest version 2 omits complete-file
hashes. Replay still accepts version 1 manifests but does not use their hashes.
The codec ABI is 10. Build Swift and Rust components from the same revision.
No SQLite schema migration is required by these changes.

Target commits and SQLite checkpoints remain separate. Uncertain writes still
need operator investigation. This release does not add automatic crash recovery.
